# INTEGRATION

## Propósito
Conectar desarrollo de software y trabajo académico para evitar inconsistencias.

## Fuentes
**Software:** código GitHub + documentación técnica + pruebas.  
**Academia:** Word vigente + bibliografía + resultados experimentales + normativa.

## Matriz inicial

| Académico | Software | Riesgo |
|---|---|---|
| Objetivos | RF | Medio |
| Sabine | Modelo RT | Alto |

## Cambio académico → software
Registrar cambio → identificar archivos afectados → marcar `REQUIERE VALIDACIÓN` → revisar código → probar → aprobar → actualizar.

## Cambio software → academia
Evaluar impacto → actualizar documentación técnica → actualizar sección del Word → renovar evidencias/capturas → registrar.

## Regla
No declarar implementada una decisión académica sin verificar el código, ni declarar una funcionalidad como parte del alcance académico sin comprobar el documento vigente.
